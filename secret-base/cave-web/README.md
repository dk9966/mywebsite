# Cave scene on the web (`/cave`)

The Blender cave (`platform-controls/cave-platform-sliders.blend`) rendered in
three.js, with the Voxelize world recessed into the hole behind the central
platform.

## Run it

```sh
npm run dev            # http://localhost:5174/cave
npm run voxel-server   # Voxelize world in the rear hole (ws://localhost:4100)
```

Without the voxel server the cave still renders; the hole simply stays dark.

## How the lighting works

The scene is lit by 55 Cycles lights (spots with soft radii, ~40 area lights,
light linking for the central deck and the cave bounce), multi-bounce GI and ten
volumetric mist boxes, then graded with AgX "Medium High Contrast" at +0.25 EV
and an amber-only Fog Glow in the compositor.

Direct light is computed live; only what three.js cannot compute is baked.
Nothing that depends on the light's or the viewer's position is frozen into a
texture, so shadows, highlights and reflections are right from every camera
position (an earlier full-lighting bake showed ghost highlights and silhouettes
away from the scene camera).

| Blender feature | Web counterpart |
| --- | --- |
| Every light (power, colour, cone, size, diffuse/specular factors, light linking) | shaded per pixel in `caveLighting.ts`: Lambert + GGX, Blender's units (P/4π for point/spot, P/π for area, irradiance I/(d²+r²), checked against Cycles bakes) |
| Soft shadows | PCSS shadow maps (one 1024² tile per light ≥ 40 W and every spot), rendered once at load; the deck grates cast through their holes |
| Multi-bounce GI | `light-N`: Cycles' *indirect* diffuse only (no direct light, no shadows), half resolution |
| Surface materials | `albedo-N` (base colour + coverage), `detail-N` (normal incl. bump, roughness, metallic / specular level) baked from the Principled inputs |
| Emissive fixtures | exact emission colour × strength (HDR, feeds the bloom) |
| Glass pane / holo glass | translucent / additive materials |
| 10 mist volumes | default: `caveBeams.ts`, the cave-wide volume's veil in closed form plus each spot's beam (its cone marched through its beam mist, with the surface shadow maps), ~3 ms; `?haze`: the full ray-march of all ten volumes, every spot and the large area lights (slow) |
| Compositor Fog Glow (only where R − B > 0.5) | bloom with the same amber mask, threshold and knee |
| AgX + look + exposure | `view-lut.bin`, a 48³ LUT generated by Blender's own colour management |
| Camera (24 mm, shift Y 0.0305) | same lens, sensor fit and lens shift |

Approximations: area lights are treated as spheres of the same area (exact on
axis), lights under 40 W are unshadowed (small local washes), glossy
reflections of the cave use the baked indirect light as a uniform environment,
and emissive surfaces do not light their surroundings directly.

## Re-export after editing the .blend

Save the .blend, then:

```sh
npm run export-secret-base-cave
```

This runs `export_cave.py` in a background Blender (never touching the open
file), bakes per chunk the base colour, parameters, specular level and normal
(a few samples each) and the indirect light (512 samples, half size), writes
`models/cave/`, and converts the atlases to WebP (`encode_atlases.mjs`).
`--quick` bakes 2K atlases at 16 samples for a pipeline check in ~5 minutes.

Exporter details worth knowing (each one was a visible mismatch before):

- Selection follows *render* visibility: the main haze volume
  (`Metal | Atmosphere | dry cave volume`) is hidden in the viewport but renders.
- Copies take the evaluated mesh's materials (geometry-node materials on the
  console) and then each object-linked slot (the "Right steel | …" overrides).
- Object / Generated texture coordinates are stored per copy as attributes
  and the procedural steel/rock materials read those, so joining copies into
  bake chunks does not move their noise. Transforms are applied before joining
  (a mirrored join target bakes the whole chunk black).
- Copies keep their light-linking receiver collections, and a bake chunk never
  mixes linking groups.
- `BakeUV` is only the bake target; shading keeps the original render UV.
- The indirect bake must see light on metals too, which have no diffuse lobe:
  while it runs, each material shows a white diffuse surface to camera rays
  (the baked texel) and its real self to every bounce.
- `--save-prepared=PATH --prepare-only` saves the bake-ready scene; rendering
  it should match the reference to within sampling noise.

`gen_view_lut.py` regenerates `view-lut.bin` if the view transform, look or
exposure change.

## Checking against Blender

```sh
# references: final image + raw EXRs with/without mist (camera resolution)
Blender --background SCENE.blend --python secret-base/cave-web/render_reference.py
Blender --background --factory-startup --python secret-base/cave-web/exr_to_display.py -- \
  reference/linear-no-haze.exr reference/blender-no-haze.png \
  reference/linear-with-haze.exr reference/blender-haze-nobloom.png
# web captures at the same size, then a region-by-region comparison
node secret-base/cave-web/capture.mjs out.png "&nobeams&nobloom&novoxels"
node secret-base/cave-web/compare.mjs secret-base/cave-web/reference/blender-no-haze.png out.png
```

Haze is checked in linear light: dump the reference EXRs
(`exr_dump.py`), capture the page with `&haze` (or the default beams) and with
`&nobeams`, both using `&logout`
(log-encoded scene-linear output), and run `haze_compare.mjs`. Bloom:
`bloom_compare.mjs` on captures with and without `nobloom`, against the same
difference of `blender-camera.png` and `blender-haze-nobloom.png`.

URL switches: `haze` (full mist march instead of the beams), `nobeams`, `nobloom`, `novoxels`, `noshadows`, `msaa=N`, `debug=albedo|normal|light|…`, `locked` (fixed scene camera),
`logout`, and tuning overrides `hazeGain`, `hazeAmbient`, `bloomIntensity`,
`bloomRadius`, `bloomThreshold`, `bloomSmoothing`. Two fresh reviewers score
captures with `scoring-rubric.md`.

## The voxel box

`voxel-server/` is a small Voxelize server (Rust, `voxelize` 3.0) with one
bounded world, `cave-box`: a 28 × 22 × 18-block stone shell, open toward the
camera, with grass terraces, an oak, ore seams and lantern lighting. Edits are
saved under `voxel-server/data/`; delete that folder to regenerate the world.

`VoxelBox.tsx` places the grid at 0.5 m per block on the hole frame exported in
`manifest.json` (`hole`), so the 14 m × 11 m box face covers the 9.8 m × 8 m
opening from every allowed camera angle. Block textures are generated in code
(`voxelTextures.ts`). Vite must not pre-bundle `@voxelize/core` (its workers
load next to its own dist), see `vite.config.ts`.
