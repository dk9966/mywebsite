# Bridge — procedural geometry and texturing

Everything about this asset is generated by these scripts. No Blender, no
hand-modelled mesh, no external assets. Unlike the island pillar there is no
input mesh at all: the only input is the reference sheet's dimensions, and the
output is `../bridge.glb`.

```
python build_bridge.py      # numbers in config.py -> textured bridge.glb
python validate.py          # structural checks on the exported glb
python render_preview.py    # -> ../bridge_preview.png
```

Requires `numpy` and `pillow` (`pip install -r requirements.txt`). About five
seconds end to end; `build/` holds the intermediate texture maps and is safe to
delete.

`glb.py`, `noise.py` and `raster.py` are the island pillar's modules,
byte-identical. `reshape.py` is the pillar's with the pillar-specific top-cap
reshaping dropped and one optimisation added.

## The model

4.00 m long, 2.00 m wide, 0.30 m tall. Origin at the centre of the span, on the
ground plane, with X along the length and Z across the width. 574 triangles,
0.26 MB, two materials.

**There is no railing.** The reference sheet's posts, caps and two runs of rail
per side are gone, and so are the side beams that ran under them. The deck is
now a bare plank surface that cantilevers 95 mm past the slab on each side, so
the plank ends are the outermost thing on the model and are what put
`|z| = 1.000`. Length and width still match the drawing exactly; the height does
not and should not, since the drawing's 60 cm measured to the top of a handrail
that no longer exists. The envelope is restated at 30 cm rather than inherited.

**The asset carries no light sources either.** The blue and violet strip lamps
and the glowing runs along the deck edge are gone. What remains that is technically
emissive is the edge highlight, which is not a light: it is the specular a hard
machined edge would catch from the environment, faked as emissive so that it
survives on faces turned away from the key light. A model this dark is
unreadable in shadow without it. `validate.py` asserts there are exactly two
materials, that neither carries an emissive tint of its own, and that the edge
LUT never clips — so a lamp cannot quietly creep back in.

## Everything is a sheared box

There is no mesh format anywhere in the pipeline. The bridge is a union of
axis-aligned prisms whose four top corners sit at `deck(x) + offset` rather
than at a constant height, so every part — slab, planks, ribs, abutments —
bends with the arch for free and all six faces of every prism stay perfectly
planar. That planarity is what keeps the block joints crisp and the
tangents well defined.

Long parts are cut into segments. This is not cosmetic: a single prism spanning
the whole slab would chord the arch and the crown would sag by centimetres.
The facet count and the number of visible joint collars stay separate knobs
(`segments` and `collar_stride`) for the parts that still have them.

Nothing is booleaned. Parts are deliberately sunk into each other — planks into
the slab, the slab into the abutment plinths — and the interior faces are
deleted afterwards. Getting 76 prisms to butt exactly is both harder and worse:
exact butts produce coincident surfaces, which is the one thing the cleanup
cannot fix by deletion.

## The height is solved, not chosen

X and Z fall out of the part positions exactly: the abutment base course sets
both `|x| = 2.000` and `|z| = 1.000`. Height does not. The tallest point is the
walking surface, and that is made of discrete planks, so its true maximum sits
on whichever plank straddles the centre — and only on that plank's own top
face, a chord of the arch and slightly below it.

Rather than fudge a thickness until it looked close, `solve_rise` bisects on the
arch rise until the model's measured maximum lands exactly on `ENVELOPE`'s
height. Height is monotonic in rise and each trial only builds a few thousand
vertices, so it converges in well under a second. `validate.py` asserts the
exported bounding box to within half a millimetre, so this cannot silently
regress when a part moves.

This is also what absorbed the railings coming off: the crown moved from the
handrail to the side beam and then to the deck itself, the target dropped from
0.600 to 0.300, and the solve simply re-converged each time — 0.1181, 0.1145,
now 0.1403. Nothing else had to be re-tuned to keep the envelope exact.

## The material

The body has **no textures at all** — a flat `baseColorFactor` of `#232428` at
roughness 0.32. This follows the island pillar, where full basecolor/normal/
roughness maps made the asset read as wet photoreal stone; the same is true of
pretending dark alloy has visible grain over every surface. The silhouette and
the edge highlights carry it.

The one textured surface is the deck. The only other map in the file is the
edge LUT.

## The edge highlight

Lifted from the island pillar, at a tenth the scale and with the second profile
removed along with the glow lines it existed for. Every sharp convex edge gets
a crisp highlight of constant *world-space* width, with no baking, no atlas and
no seams.

The trick: distance from a point to a straight edge is **linear** across a
triangle, so it interpolates exactly through the rasteriser as a vertex
attribute. For each triangle we find its sharp convex edges (dihedral above
`EDGES.min_angle`, neighbour's free vertex behind the plane), then store each
vertex's distance to the two nearest ones in `TEXCOORD_1` as `1 - d/w` — 1 right
on the edge, 0 at the band limit, negative beyond it. The LUT's zero end sits at
axis 0, so with `CLAMP_TO_EDGE` everything outside the band is handled for free,
which is what lets the stored distance stay unclamped and therefore linear.

Sharper edges get a proportionally wider band, so blunt creases produce thinner
lines. Two slots per face; no triangle on this model has more than two sharp
convex edges, so nothing is lost.

Since the two-profile packing went away with the lights, so did the LUT dead
zone and the invariants guarding it. `validate.py` now checks a simpler thing:
that no stored value exceeds 1. Anything above the LUT's peak would sample into
the clamped border on the *bright* side, holding maximum brightness instead of
falling off, and the highlight would flood the face instead of drawing a line.

## The deck

Planks are real geometry: fifteen prisms laid on a continuous slab, sunk 8 mm
into it so their undersides come out as buried faces and the grooves between
them read as grooves rather than as holes you can see the ground through.

### Where the slab is cut is not a free choice

For a while the deck had slits in it. Seen from above you could see straight
through the gaps between planks to the background; seen from below or from any
three-quarter angle the deck was solid. That asymmetry is the whole clue.

The slab was faceted on a count of its own — sixteen equal segments over
3.28 m, so 0.205 m each — while the planks sit on a pitch of 0.2133 m. The two
rhythms drift against each other, so a slab-top face would sit under a plank
across most of its width and poke into the gap beside it. `remove_buried_faces`
deletes a face only when *every* probe across it lands inside the solid, and
with seven probe points on a face that is 90% covered, all seven can miss the
sliver that is exposed. The face gets deleted, taking the floor of the gap with
it. What is left underneath is the slab's *underside*, which faces down and is
single-sided, so from above it culls away and you see the background — while
from below it is perfectly opaque.

The fix is not a better probe pattern; it is removing the ambiguity.
`geometry.slab_edges` cuts the slab at the plank boundaries (and at the
abutment landings' inner edges), so every slab-top face is now either wholly
under a plank — correctly deleted — or wholly in the open — correctly kept.
None of the deleted faces straddle open deck.

`validate.py` now proves this rather than trusting it: 2340 probes over the
walkway, each checking that *some* upward-facing triangle lies beneath it. The
test is scoped to the slab's own width, not the model's — the gaps between the
overhanging plank ends are open by design. `render_preview.py` also gained a
plan view, since overhead is the only angle from which this class of hole is
visible at all.

### The texture

The texture is a single tile whose **u repeats once per plank pitch** and whose
**v spans the walkway**, mapped by planar XZ projection. That alignment is the
whole point of the projection being planar rather than per-face: the painted
joint lands exactly on the real groove, and the bolt rows land in the same place
on every plank. It also lets the abutment landings — solid plate with no grooves
cut into them — carry on the plank rhythm without a seam in the pattern.

The bolts are drawn as ellipses in tile space because the tile is 8.8× wider in
world units than it is tall; they come out round on the deck. Maps are rendered
at 3× and box-filtered down, since the joints and bolt rims are thin hard-edged
shapes and at output resolution they bead into dotted lines at grazing angles —
which, on a deck, is most of the time.

The deck keeps its edge highlights (`emissiveTexture` on UV1 alongside
`baseColorTexture` on UV0), because the plank grooves are where most of the
model's edges are.

## Why triangles were showing up on flat panels

Every prism is sheared onto the arch, so its side faces are not quite planar and
the diagonal each quad gets cut along ends up with its two halves facing very
slightly different ways. Flat-shaded, each half catches the light differently
and the cut line shows up as a visible triangle running across what should be a
single panel.

Neighbouring triangles therefore share a single averaged normal wherever the
bend between them is below `SHADING.smooth_deg` (20°) — 438 of 760 shared edges
here. Anything sharper is a genuine crease and stays perfectly sharp, which is
what keeps every block joint on the model reading as a block joint. Tangents are
rebuilt against the smoothed normals to match.

Only exported faces take part in the averaging. Buried faces are interior and
their orientation is arbitrary; blending a visible normal with one of those
corrupts the shading of a surface that looked fine.

## Fixing the sparkle

**Coincident surfaces.** Because the model is an un-booleaned union, ~37% of its
faces sit buried inside the solid, many exactly coplanar with a visible face.
Two surfaces at identical depth flicker against each other as the camera moves
and no amount of MSAA fixes it.

`reshape.remove_buried_faces` finds them with a generalized winding number.
Plain ray-parity does not work on a union of overlapping shells — a point inside
two of them gets an even crossing count and reads as outside. Two details
matter, both inherited from the pillar and both still load-bearing here: a face
counts as buried only if solid lies on *both* sides, and every sample across the
face must agree, since parts here are routinely half-embedded (a plank sunk into
the slab, the slab running into the abutment plinths) and a centroid-only test
deletes them outright and punches holes. Note that "every sample must agree" is
a necessary condition and not a sufficient one — see the deck section for the
case where seven samples all agreed and were all wrong.

That removes 338 of 912 triangles with no visible change.

**Remaining ties.** `break_coplanar_ties` nudges one face of any surviving
coincident pair inward by 0.4 mm, far below visible scale, which gives the depth
test a stable winner. With the railings gone there are none left to nudge, but
`validate.py` still asserts zero coincident pairs remain across the file.

**The LUT sampler.** The edge LUT is a ramp, not a picture, and UV1 sweeps a
huge range across a single face. With mipmaps the derivative is large enough
that the GPU would collapse the entire falloff curve into its average. It
samples LINEAR with no mipmaps, asserted in `validate.py`.

**Vertices are split per face.** Sharing the eight corners of a prism between
its twelve triangles is the natural way to build one and the wrong way to ship
it: normal smoothing needs to write a different normal into each face meeting at
a corner, and tie-breaking needs to move one face without dragging its
neighbours. Building welded and exporting split gave a normal 90° off its own
face on the first run. Welding happens where it is actually wanted — inside the
edge detector, by rounded position.

## A note on the preview renderer

`render_preview.py` reads geometry, materials and textures back out of the
exported glb rather than reusing the build script's in-memory state — so a
preview reflects the file, not the intent. `raster.py` exists for the same
reason: an earlier version of the pillar's previewer shaded flat facets and
ignored the normal map, so generated previews looked clean while the real asset
was covered in speckle. It does tangent-space normal mapping and GGX specular.

## Files

| file | role |
| --- | --- |
| `config.py` | every tunable value — envelope, arch, part positions, colours |
| `geometry.py` | prism assembly, the arch, and the rise solve |
| `build_bridge.py` | main build: cleanup, UVs, edge detection, glb export |
| `textures.py` | the edge LUT and the deck maps |
| `reshape.py` | buried-face removal and coincident-surface tie-breaking |
| `noise.py` | tileable fbm (FFT-shaped) and Worley noise, height→normal |
| `glb.py` | minimal glTF 2.0 binary reader/writer |
| `raster.py` | software PBR rasteriser (normal mapping, GGX, analytic env) |
| `render_preview.py` | renders previews by reading the exported glb back |
| `validate.py` | structural checks on the output |
