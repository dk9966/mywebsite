# Island pillar — procedural texturing

Everything about the island pillar's look is generated by these scripts. No
Blender, no hand-painted maps, no external assets. The only input is the
untextured mesh; the output is `../island_pillar.glb`.

```
python build_pillar.py      # untextured mesh -> textured island_pillar.glb
python validate.py          # structural checks on the exported glb
python render_preview.py    # -> ../island_pillar_preview.png
```

Requires `numpy` and `pillow` (`pip install -r requirements.txt`). Roughly 30
seconds end to end; `build/` holds the intermediate texture maps and is safe to
delete.

## What the material actually is

The pillar body has **no textures at all** — just a flat `baseColorFactor` of
`#232529` at roughness 0.35. Earlier versions had full basecolor/normal/roughness
maps with fractal cracks and micro-scratches; the result read as wet photoreal
stone, which is the wrong look. The silhouette and the edge highlights carry it
instead, which is also why the file is 1.8 MB rather than 10 MB.

The only textures in the file are the top platform's paving maps and a 256px
lookup table.

## The edge highlight

This is the interesting part. Every sharp convex edge gets a crisp emissive
line of constant *world-space* width, with no baking, no atlas and no seams.

The trick: distance from a point to a straight edge is **linear** across a
triangle, so it interpolates exactly through the rasteriser as a vertex
attribute. For each triangle we find its sharp convex edges (dihedral angle
above `EDGES.min_angle`, neighbour's free vertex behind the plane), then store
each vertex's perpendicular distance to the two nearest ones in `TEXCOORD_1`,
divided by the band width.

A 2D LUT resolves `min(u, v)` into the falloff curve, sampled with
`CLAMP_TO_EDGE` so anything past the band reads as zero — which is what makes
unclamped per-vertex distances safe. Sharper edges get a proportionally wider
band, so blunt creases produce thinner lines.

Two slots is exactly enough here: no triangle in this mesh has more than two
sharp convex edges, and `build_pillar.py` asserts it. If you swap in a mesh
where that fails, the assert fires rather than silently dropping edges.

Because it drives `emissiveTexture`, the lines stay visible on faces turned away
from the light, which is what keeps the geometry readable in shadow. Set
`EDGES.emissive` to `[0, 0, 0]` to switch it off, or to a blue tint for a
glowing-vein look.

## The top platform

Concentric courses of paving whose brick count scales with radius, so arc
length per brick stays roughly constant. Alternate courses are staggered by
half a brick. A twelve-wedge medallion sits in the middle and a ring of 48
radial kerb slabs finishes the rim. Course boundaries are nudged by low
frequency noise so they aren't machine-perfect.

Faces qualify as platform by pointing up, sitting above y=5.9 and falling
inside the crenellation ring — those rim blocks stay plain body material. The
UVs are a planar XZ projection scaled to the disc radius, which is what keeps
the courses perfectly concentric.

## Files

| file | role |
| --- | --- |
| `config.py` | every tunable value — colours, edge widths, paving layout |
| `build_pillar.py` | main build: face selection, UVs, edge detection, glb export |
| `textures.py` | the edge LUT and the paving maps |
| `noise.py` | tileable fbm (FFT-shaped) and Worley noise, height→normal |
| `glb.py` | minimal glTF 2.0 binary reader/writer |
| `raster.py` | software PBR rasteriser (normal mapping, GGX, analytic env) |
| `render_preview.py` | renders previews by reading the exported glb back |
| `validate.py` | structural checks on the output |

## A note on the preview renderer

`raster.py` exists because previews that lie are worse than no previews. An
earlier version shaded flat facets and ignored the normal map entirely, so the
generated previews looked clean while the real asset was covered in speckled
micro-detail in an actual engine. It now does tangent-space normal mapping and
GGX specular, and `render_preview.py` reads geometry, materials and textures
back out of the exported glb rather than reusing the build script's in-memory
state — so a preview reflects the file, not the intent.
